# Implementation contracts

Single-user local research app, loopback only. Python FastAPI serves built React assets. No signing, wallet connection, blockchain submission, simulations, paid endpoints, or arbitrary URL proxy.

Modules are independent: `storage.py` handles persistence, `app.py` owns HTTP and the serialized research worker, `providers.py` and `collector.py` handle native reads, `discovery.py` handles bounded public cohorts and identity checks, `candidate_import.py` handles offline identifier imports and saved-universe derivation, `evidence_audit.py` handles separate raw transaction-set checks, `history_evidence.py` derives local collection receipts, `chronology_evidence.py` reconciles shared per-slot evidence, `report_rebuild.py` freezes/loads saved native inputs, `investigation.py` reconstructs narrowly recognized spot swaps and current token controls, `research.py` handles conditional observations, and `accounting.py` evaluates strict FIFO metrics. `frontend/` contains the React interface. The launcher holds a nonblocking OS lock for the entire lifetime of each data directory's running server.

## API

Bootstrap: `GET /api/bootstrap` with `X-Launch-Token` from URL hash `#session=...`; returns `{csrf,version}` and sets HttpOnly SameSite Strict cookie. All mutations require `X-CSRF-Token`. Every endpoint enforces loopback Host and same Origin. React uses relative `/api` URLs.

`GET /api/state` returns `{version,methodology,settings,preset,scans,discovery_cohorts,candidate_universe,evidence_audits,reports,watchlist,usage,provider,storage}`. Reports here are full reports for this bounded local pilot. `GET /api/usage` exposes the same quota view. `GET /api/provider/manifest` exposes the dated method-cost manifest. Errors use `{detail:string}`.

Discovery is the primary flow:

- `POST /api/provider/key` accepts exactly `{api_key}` and connects the key for a bounded setup pilot without inventing free-plan entitlement or billing dates. It clears monthly provider confirmation; changing a key does not reset the existing setup ledger.
- `POST /api/discovery` accepts optional `{pool_cap,candidate_cap,validate_cap}`, defaults to `{pool_cap:3,candidate_cap:20,validate_cap:8}`, and returns `{cohort_id}`. API ceilings are three pools, the configured candidate cap (at most 20), and eight native identity validations. Only one research batch is active at a time.
- `POST /api/discovery/import` accepts exactly `{addresses:[...]}`: 1–1,000 public identifiers validated before persistence, first-occurrence deduplication, at most the configured candidate cap retained, omitted and duplicate rows counted. Returns `{cohort_id,counts}`. It performs no provider reads and does not verify identity.
- `GET /api/discovery/universe` returns a derived saved candidate universe, deduplicated by address with dated original memberships, pool sets, evidence and omission counts. It performs no provider reads and does not mutate cohorts or financial reports.
- `GET /api/discovery/{id}` returns the persisted cohort and its evidence/limitations.
- `POST /api/discovery/{id}/audit` accepts optional `{addresses:[...]}` or selects eligible candidates up to the configured audit cap (at most five). It requires native identity verification as a system-owned economic signer in the same cohort and a connected key; it returns `{scan_id,budget_mode}`.

The secondary manual/monthly flow uses `POST /api/provider` with `{api_key?,free_plan_confirmed:true,cycle_start,cycle_end}` and `POST /api/provider/test` with `{address?}`. Monthly manual scans require confirmed actual dates and a passed address-specific capability result. The cycle end date is exclusive, and an active confirmed cycle cannot be changed to reset usage. A basic test without an address does not enable wallet scans. `POST /api/scans` accepts `{addresses:[...],window_days?,source?}`. `POST /api/scans/{id}/pause` and `/resume` preserve checkpoints; an explicit resume can grant a further bounded collection tranche under the same global cap.

`GET /api/evidence/example` downloads the packaged public `raw-evidence-v1` mainnet example. `POST /api/evidence/audit` accepts that raw bundle directly and returns `{audit_id,id,created_at,bundle_hash,...audit_result}`. `GET /api/evidence/audits/{id}` reads the separate immutable saved result and `/api/evidence/audits/{id}/export` downloads JSON. These operations make no provider reads and do not create or upgrade a wallet report. The audit POST refuses new archiving below the configured free-disk reserve and has a 4 MiB request limit; ordinary JSON requests retain the smaller general limit.

`POST /api/demo` creates synthetic, visibly labeled offline reports without provider calls. `GET /api/reports/{id}` returns a report. `PUT /api/settings` accepts `{preset?,limits?,refresh_minutes?}`. `POST /api/presets/preview` accepts `{preset}` and returns `{reports:[...]}` from cache without overwriting saved snapshots or making provider calls. `POST /api/watchlist` accepts `{address,label}`; `DELETE /api/watchlist/{address}` removes it. `GET /api/export/reports/{id}.json` and `.csv` export saved reports. `POST /api/reports/{id}/rebuild` creates a new current-method live report from archived primary records and returns `{report_id}`. It requires the original collection-job context, preserves the saved report window/preset and earlier snapshot, links `rebuilt_from`/`previous_methodology`, and records `{source:"archived-native-records",provider_requests:0,retained_window:true,retained_preset:true,mint_observations_refreshed:false}`. It does not refresh mint observations or request missing data. Demo/preview reports, absent/corrupt/duplicate primary identities, mismatched source windows/jobs and inadequate free disk are rejected.

`POST /api/reports/{id}/enrich` fetches at most five current mint observations. `POST /api/backup` creates a verified local backup. `GET /api/evidence/{sha256}` verifies and returns archived JSON. No endpoint returns the provider key.

State settings: `{limits:{candidate_cap:20,deep_audit_cap:5,transaction_limit:10000,wallet_credit_limit:20000,helius_cap:800000,discovery_pause:600000,min_free_disk_mb:2048},refresh_minutes:0}`. Free-mode workload caps may only be lowered. Monitoring is disabled at zero; values 15–1440 enable in-process watchlist rotation only with the confirmed monthly configuration and an address-specific capability result.

Provider: `{configured,storage:"os-keyring"|"session-only"|"environment"|"none",free_plan_confirmed,capability_status:"untested"|"passed"|"failed",last_test,cycle_start,cycle_end,calibration_address?,capability?}`. Usage: `{used,reserved,cap,remaining,cycle_start,cycle_end,manifest_version,mode:"setup-pilot"|"monthly",billing_cycle_verified,setup_pilot,public_discovery}`. `billing_cycle_verified` indicates accepted operator confirmation/date validation, not remote provider billing verification.

Setup mode uses the durable Helius cycle identifier `setup-pilot` with a 200-credit lifetime cap per data directory, including discovery identity checks, investigations and mint-control queries. It never resets on restart or key replacement. Each wallet collection initially has at most 20 transactions and a 30-credit tranche; current mint checks remain inside the shared global cap. Account scope is capped at 200 identities in setup mode and 1,000 in monthly mode, with excluded accounts retained as coverage gaps. Monthly mode uses the confirmed cycle identifier and at most 800,000 credits, pausing new discovery at 600,000. GeckoTerminal discovery and enrichment share 200 requests per calendar day, an eight-per-minute rate gate, and 15-minute observation caching. All quotas include reservations and conservatively charge dispatched failures/timeouts.

Preset uses scalar decimal strings and ints: `{name,version,window_days:30,verification_days:90,min_profit_sol:"5",min_realised_roi_pct:"10",min_median_roi_pct:"5",min_win_rate_pct:"50",max_win_rate_pct:"85",min_hold_hours:"1",max_hold_hours:"72",min_positions:50,min_positions_90d:100,min_mints:20,max_mints:100,max_rapid_sale_pct:"10",min_avg_buys:"1",max_avg_buys:"2",min_avg_sells:"1",max_avg_sells:"3",min_positive_weeks:3,max_contribution_pct:"25",require_positive_economic_pnl:true}`.

Report: `{id,scan_id,address,label,source:"demo"|"live",created_at,window:{start,end},methodology:"fifo-v3",policy:"MATCH"|"MISS"|"UNRESOLVED",evidence_status:"verified"|"partial"|"unknown"|"stale",metrics:{key:{value:string|null,unit,status:"known"|"unknown",population,reason?,evidence:[hashes]}},checks:[{key,label,state:"PASS"|"FAIL"|"UNKNOWN",actual:string|null,expected,reason}],coverage:{...},positions:[...],events:[...],metric_intervals:{report_period,four_weeks,verification_90d},metric_coverage:{metric_key:{interval,start,end,status,source,evidence,reason?,metric_status,...}},findings:[{severity,title,detail,evidence?:[]}],evidence:[{hash,kind,signature?}],counts:{closed,open,interrupted,unresolved},notes:[...],collection_input_hash?,rebuilt_from?,previous_methodology?,rebuild?,qualification?,copy_review?}`. Historical saved snapshots may retain `fifo-v1` or `fifo-v2`; they are never silently relabeled or recalculated. Monetary JSON values are strings; native quantities are integer strings. Metrics keys: `profit_sol,realised_roi_pct,median_roi_pct,win_rate_pct,median_hold_hours,completed_positions,completed_positions_90d,traded_mints,rapid_sale_pct,avg_buys,avg_sells,positive_weeks,largest_contribution_pct,economic_pnl_sol`. Uncertain eligible positions block affected metrics. Known FAIL survives other UNKNOWN. MATCH requires all evidence gates and metrics known.

Live reports additionally expose `research` and `token_risk`. `research` keeps `history_complete` and `wallet_profit_verified` false for sampled live work, separates `observed_profit_sol`/`known_matched_profit_sol` from `conditional_observed_lot_profit_sol`, and records supported-swap counts, unmatched or unresolved-basis sales, conditional holding/exit times, evidence and limitations. Conditional figures assume no undiscovered earlier inventory/intervening flows, exclude unmatchable sales, and never mutate strict meme classifications or emit a strict match. `token_risk` contains current mint observations with tri-state gates, findings, evidence, `status:"FLAGGED"|"UNRESOLVED"`, and `safe:null`; current revoked authorities do not prove historical or future safety.

Read paths decorate cached reports with `qualification` and `copy_review`, including `/api/state`, individual report/cohort reads and report exports, without provider calls or rewriting the stored financial snapshot. Saved non-preview live reports also receive independent `history_assessment` and `position_assessment`, each `{saved_methodology,current_methodology,state:"current"|"rebuild_required"|"missing",reason}`. They compare the saved methods with current `history-evidence-v9` and `account-position-evidence-v11` separately; `current` describes the method, not completeness. Read-time annotations leave the original coverage, metrics, window and preset unchanged, including in report exports. `qualification` contains `{report_id,preset_version,preset_snapshot,methodology,window,financial_policy,evidence_status,profit_sol,qualified,failed_checks,unknown_checks,checks,reason,notes}`. It requires a non-preview live saved `MATCH`, verified evidence, current accounting `METHODOLOGY` (`fifo-v3`), current history receipt and position methods, known strict profit, and all required named saved-policy financial/evidence checks appearing exactly once and explicitly passing. The default unchanged strict preset includes every PDF page 9 starting rule and evidence gate; edited presets qualify only against their identified saved rules. Old or missing methods carry a rebuild reason and cannot qualify under the current methods. Its scope is the saved preset/window; the frontend compares the exact saved preset snapshot with active settings before counting current matches. Conditional research profit, synthetic reports and missing or repeated checks never qualify. Edited presets remain identified as current custom settings. Cached qualification/review does not consume provider credits or reset the exhausted setup ledger.

`copy_review` contains `{scope,conditional,checks,findings,unknown_checks,notes}`. It records factual timing comparisons (`OBSERVED`), unresolved investigations (`UNKNOWN`), current token flags, and explicitly supplied reviewed checks. Missing token controls stay in explicit unknown checks/counts and the original `token_risk` evidence panel; they do not create accusation findings. True failed controls and factual observations remain visible. A final hold meeting the preset minimum while 90% sold within five minutes produces an evidence-linked timing finding, not a strict policy failure or allegation of intent. The observed first-sale-within-five-minutes share retains its population and chronology conditions. Follower exploitation, creator links, liquidity withdrawal and holder concentration require explicit reviewed primary evidence present in the report; missing review never becomes `PASS`. Token-specific reviewed passes cannot clear uninspected observed mints. No copy safety score, copied-fill estimate, replay, paper trading or execution is produced.

Scan: `{id,source:"demo"|"live",discovery_source?,budget_mode:"setup-pilot"|"monthly",discovery_cohort_id?,status:"queued"|"running"|"paused"|"completed"|"failed",stage,created_at,window:{start,end},addresses,audit_addresses?,deferred_addresses?,progress:{wallets_completed,wallets_total,pages,transactions,credits,unresolved},reason?,checkpoint:{...}}`. Progress cumulatively preserves completed wallet totals through pauses/restarts. Completion of a job does NOT mean complete evidence.

Discovery cohort: `{id,version,created_at,cohort_date,source:"public-pool-discovery"|"user-list",status:"queued"|"running"|"partial"|"completed"|"paused"|"failed",stage,universe,candidates,rejected_leads,evidence,misses,sample,counts,limitations,audit_scan_ids?}`. The sample is current trending-pool page one, SOL-quote pools prioritized, up to 300 returned trades per selected pool, and a 24-hour `[start,end)` window. Candidates retain observed buy/sell counts and signatures, evidence hashes, reason, and `status:"candidate"|"rejected"|"unresolved"`. Native checks establish a sampled economic signer with owned token movement and current system-account identity; they do not establish a human operator, full history, profitability, legitimacy, or safe copying.

Saved universe: `{version:"saved-candidate-universe-v1",candidates:[{address,source:"saved-universe",status,first_seen,last_seen,origin_types,cohort_ids,origins,pools,signatures,evidence,report_ids,audit_eligible_cohort_ids,states:{observed,identity_checked,sample_audited,history_reconstructed},stage,...}],counts,limits:{candidate_cap},limitations}`. Origins preserve their own date, pool membership, evidence and verification state. The display cap counts omitted candidates/memberships without deleting them. Imported cohorts use `public-address-import-v1` and remain listed/unresolved; no unverified import advances identity or history. A successful native sampled identity, an evidence-linked partial live sample report and reconstructed history are distinct stages. History reconstruction additionally needs explicit complete ownership/history coverage, the current accounting method, verified evidence and passing history/identity/basis/positions/fees checks. A completed bounded job alone never advances a stage. Audit eligibility belongs to its verified original cohort, not the merged address list. No profit ordering or complete 30-day universe coverage is inferred.

## Storage interface (root implements)

`Store(data_dir)`, `get(kind,id,default=None)`, `list(kind)`, `put(kind,id,payload)`, `delete(kind,id)`, `archive(payload)->hash`, `evidence(hash)->payload`, `reserve(provider,method,cost,cycle,cap)->reservation_id`, `dispatch(reservation_id)`, `settle(reservation_id,charge=True)`, `release(reservation_id)` (only undispatched reservations), `usage(provider,cycle,cap)->dict`, `backup()->dict`. Exceptions `QuotaExceeded` and `EvidenceError`. SQLite monetary costs are INTEGER credits, decimal accounting values in JSON strings. Atomic reservations include outstanding usage. `cycle` is an explicit ledger identifier: the actual confirmed provider start date for monthly mode, the literal `setup-pilot` for bounded native setup, or the current calendar date for public observations. Conservatively charge dispatch timeouts.

## Collector interface

`Gateway(store,key,cycle,cap=800000,rate=3,transport=None)` provides async `rpc(method,params)` and `capability_test(address=None)`. Static native read allowlist with versioned costs. `collect_wallet(gateway,store,address,start,end,limits,checkpoint=None,progress=None,should_pause=None)` async -> `{transactions:[{signature,raw,evidence_hash}],coverage:{...},evidence:[...],checkpoint:{...},snapshot:{...}}`. Progress callback takes `{stage,pages,transactions,credits,checkpoint}`. `CollectionPaused(reason,checkpoint,partial=None)` preserves partial output. Account scope remains explicitly partial without independent ownership history. Durable `collector_checkpoints` contain compact account identities and immutable evidence references; the app places `collector_ref` in scan records instead of embedding the full checkpoint in `/api/state`. Archived snapshot/transaction bodies are read only when needed. Legacy inline checkpoint records are migrated to references at startup. Do not import root app.

## Accounting interface

`analyze(events,start,end,opening_equity=None,closing_equity=None,external_deposits=None,external_withdrawals=None,history_complete=True,*,interval_coverage=None)->dict` returns metrics/positions/counts/findings. The normalized-input function trusts its caller's history declaration. Live reporting derives structured evidence requirements from archived collection receipts; unresolved global ownership, basis, classification and boundary valuation keep live historical evidence partial. Changing the boolean without satisfying those requirements cannot establish a wallet metric or qualification. Events are documented in `accounting.py`. Four-week consistency uses all corresponding realised slices and unallocated overhead in the exact independent `[end − 28 days,end)` interval, including activity outside a shorter display window. Its weekly rows include status, reason and primary evidence references. `metric_intervals` describes report-period, four-week and 90-day coverage; `metric_coverage` maps each metric to its interval and calculation status. Explicit `interval_coverage` records accept bounds, `complete|partial|unknown`, reason and primary hashes. For four-week consistency, missing independent coverage or unresolved weekly costs/basis yield UNKNOWN. Report-period and 90-day declarations describe their coverage while their calculations retain the separate global history/basis conditions; a complete declaration is trusted normalized input, not independently validated raw history, and cannot upgrade global live evidence. `evaluate_policy(metrics,preset,evidence_verified=False)->{policy,checks}`. `decode_transactions(transactions,address)->{events,findings,unresolved,evidence}` retains generic transfer/fee interpretation and unresolved gaps. The app builds synthetic demonstrations and live reports through the same accounting engine.

`decode_supported_swaps(records,wallet)` in `investigation.py` returns normalized events, findings and reconstruction coverage. Under `spot-v4-durable-nonce`, the prior temporary-wSOL proof remains: primary wallet-funded creation/initialization, funding/sync before the ordered debit, evidenced transfers, wallet closure, zero native endpoints and exact conservation. Persistent wSOL uses evidenced event-time endpoints; missing endpoints require appropriate primary creation or closure proof. Failed attempted instructions never prove committed ownership or lifecycle. A recognized deployed outer spot instruction must identify the investigated authority and reconcile one input/output with SOL/wSOL settlement and parsed token CPIs. Explicit outside native transfers can be isolated from consideration while their capital-flow/trading-cost role remains unresolved. Unsupported wrappers, crossquotes, other ambiguous economic instructions, missing identities, or ambiguous conservation remain unresolved. Balance deltas alone never establish a swap. Program recognition is narrower than venue-wide support; the actual positive/negative real-fixture coverage is recorded in `VALIDATION.md`.

The additional nonce-administration branch accepts only the actual System Program's exact parsed `advanceNonce` fields in the first outer instruction. It requires the investigated wallet as explicit signing nonce authority, unique account identities, a writable nonce account, the actual read-only/non-signing RecentBlockhashes sysvar, unchanged nonce lamports, and whole-record native endpoint difference equal to `meta.fee`. Other nonce operations, nested/later instructions, mismatched authorities/roles or missing conservation remain unresolved. Accepted administration is exposed in `coverage.non_economic_instructions` with source path and evidence; it is not a capital flow or invented expense. The real persistent-wSOL sale fixture proves proceeds and one linked exit fee, while its prior acquisition basis stays unknown.

`audit_raw_bundle(bundle,store=None)` in `evidence_audit.py` accepts `{version:"raw-evidence-v1",address,scope:{kind:"transaction_set",signatures:[...],accounts?:[...]},transactions:[{signature,raw,evidence_hash?}]}`. Limits are 1–20 explicitly enumerated signatures/records, 4 MiB canonical JSON and at most 1,000 declared account identifiers. It optionally archives raw records, checks canonical content hashes, raw signer/signature metadata, event-time involved owned accounts, temporary wSOL lifecycle, exact consideration/quantities/network fees and native reconciliation. Missing claimed records or involved accounts fail dependent scoped results; additional unevidenced accounts remain unknown. This boundary is the supplied transaction set, not a pagination/continuous-history proof. Unknown or unsupported reconstruction never becomes zero.

Audit result: `{version:"scoped-evidence-audit-v2",source:"raw-mainnet-records"|"unverified-import",address,scope,certificate:{version,status:"SCOPED_RECONSTRUCTION"|"INCOMPLETE",checks,wallet_history_complete:false,financial_qualification:"UNRESOLVED",scope_kind:"transaction_set",content_hash},metrics,reconstruction,events,evidence,findings,unsupported,notes}`. Checks include tri-state values, actuals, primary hashes and raw paths. Each metric contains value, status, unit, population, reason, evidence and `required_checks`. `SCOPED_RECONSTRUCTION` means the core scoped reconstruction prerequisites passed and does not imply all checks passed; chain provenance and fee allocation can remain unknown. Economic fee completeness uses individual nonzero outside movements and the actual validated decoder fee-to-trade allocation, not the signed net outside delta. Offsetting unresolved flows retain UNKNOWN even when native conservation passes. Sponsored costs are excluded only with raw payer/decoder agreement; failed instructions retain one actual fee overhead event and no committed trade. Missing, inconsistent or unallocated successful fee records cannot be described as allocated. Content hashes authenticate content consistency, not arbitrary import provenance. Reviewed-mainnet recognition is restricted to the exact reviewed PumpSwap fixture fingerprint. Wallet history, opening basis, classifications, strict closed positions, boundary valuation, 28-day consistency, wallet profit and copying safety remain unknown. Audit certificates stay separate from financial reports and cannot upgrade a global evidence gate or produce MATCH.

`inspect_token_risk(raw_mint_info,pool_observations=None)` checks present mint/freeze authorities, token controls, and explicitly supplied current observations. Complete owner concentration, creator links, historical sellability and safe execution remain unknown without appropriate independent evidence.

`summarize_research(events,start,end,history_complete=False,opening_inventory=None,findings=None)` in `research.py` returns evidence-linked conditional subset observations. The FIFO engine is reused on private copies of events and does not change source classifications or strict policy. Independent opening-inventory anchors must cover every wallet-owned account for the mint and all intervening flows; a route account's pre-balance or current account list is insufficient. The app does not manufacture such certificates.

The accounting methodology is `fifo-v3`, the conditional research definition is `supported-subset-research-v2`, and current swap reconstruction records `spot-v4-durable-nonce`. Wallet-paid acquisition fees remain in lot basis even when the purchase precedes `start`; realised disposals consume matched basis including those costs. Unambiguous supported single swaps attach buy/exit fee allocation to the retained original fee event and consume the fee once. Ambiguous outside flows, failed transactions and unsupported routes retain unallocated fees/uncertainty; sponsored fees remain excluded. The v3 accounting change gives four-week consistency its independent 28-day coverage and retains the v2 cost-allocation rules. Changing methodology requires an accounting rebuild into a new versioned result, not a cached threshold re-filter. Existing v1/v2 snapshots stay immutable as this implementation's provenance choice (consistent with PDF pages 3, 7 and 14).

`freeze_report_inputs(store,address,window,collected)` archives `saved-report-input-v1`: immutable transaction hash links plus the observed snapshot, collector checkpoint, coverage and evidence. The saved report retains its exact window/preset; `collection_input_hash` also appears in its source list with kind `saved-rebuild-inputs`. `load_report_inputs(store,report)` reconstructs primary records only through those hashes, checks identities/order/boundaries and never fetches missing sources. Reports without a frozen input manifest use their exact saved transaction evidence links; any later matching checkpoint is labeled `legacy_checkpoint_not_frozen` and cannot certify the earlier collection state. Same-slot chronology requires archived native block-signature order, never signature-text sorting. Invalid or proven contradictory block/index order still rejects loading. Inspectable time, placement and semantic-source contradictions are retained in the child so the shared evidence stages revoke their dependent results. Required selected primary records must exist; a missing linked distinct alternative remains an explicit unavailable source rather than being dropped.

`derive_history_evidence(store,address,window,checkpoint=None,collected=None,*,verification_days=90)` derives `history-evidence-v9` without provider calls or writes. It checks checksum-verified local finalized-slot/request/response receipts, known-account cursor chains/terminal pages, requested/native signature-slot-time-status/account agreement and same-slot order. Output includes frozen intervals, enumerated account scope, paging checks, record provenance, metric decisions, evidence gates (state strings), native-address metrics, limitations and recovery requirements. `paging.conflicts` records linked account/page contradictions with the account, signature, field, source hashes and competing values; each evaluated account includes its own reconciliation and record receipts. Full cursor-chain inspection remains bounded and is not certification of every supplied account. A matching receipt on another account cannot hide contradictory `blockTime`, slot, error or finality metadata. Shared per-slot assessment reconciles all linked raw transaction times, signature-page observations, block order/time receipts and checkpoint indices. Different signature orders or explicit times for one slot cannot be resolved by selecting the first or last receipt. Identical repeated receipts do not create a contradiction. Optional block time may be absent when other timing/order dependencies are supported; an explicit conflicting block time blocks the dependent result. When a raw record exists, its reconciled timestamp/slot determines interval membership at both boundaries. Raw-less boundary receipts need explicit finalized metadata and agreement across linked pages. An upper timestamp anchor must belong to a connected PASS account chain; a detached page cannot anchor an interval. Unresolved linked contradictions block dependent enumerated interval and timing decisions, while independently valid selected raw-record arithmetic keeps its separate scope.

`assess_source_consistency(records,*,accounts=(),wallet=None,source_index=None,inspected_hashes=None,page_receipts=(),indexed_receipts=(),archive_contents=None)` in `source_consistency.py` derives reusable `source-consistency-v5` without IO. Inputs are checksum-verified collector-linked `{signature,evidence_hash,raw}` records; unavailable linked sources use `raw:null`. The caller validates archive links; agreeing content is not independent mainnet authentication, wallet-history completeness or route validity. Within a complete index, every linked same-signature version contributes its required facts. Records and accounts are normalized by account identity, exact raw-unit strings and relevant program evidence rather than JSON formatting, balance-array order or hash equality. Identical repeated receipts are idempotent.

`index_source_links(references,*,authenticated_references,max_unique_hashes=40000)` normalizes the complete reference multiset before archive IO. Link equality is `(kind,hash,signature)`; recognized roles are `transaction`, `signature-page`, `block-order`, `snapshot-slot`, `owned-accounts` and `native-balance`. Optional envelope metadata and repeated identical links do not create another source. Authentication comes from persisted/frozen collector context, not a caller PASS flag. The fixed distinct-hash budget may be reduced but never raised beyond 40,000. Excess distinct hashes admit no convenient prefix. Original frozen reference lists are never rewritten or trimmed. `merge_source_manifests(*manifests)` combines mirrored lists using the greatest multiplicity of each normalized link in any one list; it retains invalid entries rather than concealing them, and does not sum mirrored copies into extra references.

`source_index_receipt(index,inspected_hashes)` recomputes `{state,complete,raw_reference_count,authenticated_reference_count,unique_link_count,unique_hash_count,invalid_link_count,invalid_authenticated_link_count,unauthenticated_link_count,omitted_link_count,inspected_hash_count,omitted_hash_count,budget:{max_unique_hashes},omitted_scope,reason,evidence}` from the index and actual attempted archive hashes. `omitted_scope` is null for complete indexing or `entire-source-set` when incomplete. History adds `universe:"frozen-manifest"|"persisted-native-checkpoint"` and exposes the same receipt at `history_evidence.source_set` and `history_evidence.source_consistency.source_set`. Malformed/unauthenticated links, malformed authenticated links, omitted members of the authenticated universe, unsupported distinct-hash budget or uninspected indexed hashes leave the receipt UNKNOWN. The complete authenticated universe stays visible even when a declaration selects fewer convenient links. An attempted missing/corrupt archive is inspected for counting, but its dependent content facts remain missing/invalid; inspection completeness is not content validity or independent mainnet provenance.

The source-set receipt reaches account/native groups as a required `source_set` check. Incomplete inspection cannot certify an episode or silently bypass the shared IO budget by reopening omitted archives. This release conservatively propagates an unproven omitted scope to dependent results; selective preservation requires a complete index and supported placement/exclusion proof. Existing native raw-reference limits remain separate: more than 40,000 references keeps observed/period native totals UNKNOWN even when deduplicated scoped account inspection is complete.

The authenticated universe normally comes from the persisted collector checkpoint. An older frozen checkpoint has independent authority only when the actual saved non-preview live report binds its `collection_input_hash` to a checksum-valid `saved-report-input-v1` manifest with matching wallet/window and exact checkpoint. Internal load results carry `frozen_report_id` and `frozen_input_hash` for that verification. An unsaved dict, caller flag or transient trimmed checkpoint subset cannot declare a complete historical source universe. An append-only later checkpoint does not replace a supported older saved snapshot.


### Typed archive contents and R12 dependencies

`source_archive_receipts` preserves each authenticated link under `source_consistency.archive_contents`, separately from `source_set`. The latter proves enumeration and attempted inspection, not usable contents. `archive_contents` has `state`, `counts:{links,usable,unresolved}` and `receipts`. Each receipt retains `kind`, `hash`, optional declared `signature`, `state`, `read_state`, `validation_state`, independently derived `scope:{account,signatures,slot}`, `reason`, `evidence` and a recovery action with `provider_requests:0`.
